Birthday Reminder

162 students, their photos, and a window that finds you instead of the other way round.

Install (about 20 seconds)

  1. Put this whole folder wherever you keep things — Documents is fine. Keep it together; the app, the photos and the spreadsheet all live here.
  2. Double-click Install.command.
macOS will block it the first time. That is normal, and this is the quick way through.
  1. Double-click Install.command. macOS says it cannot be opened and offers Move to Trash or Done. Click Done — never Move to Trash.
  2. Click the button below. System Settings opens on the right page.
  3. Near the bottom it now says "Install.command was blocked…" Click Open Anyway, then Open Anyway again if it asks, and put in your Mac password.
  4. It installs. You only ever do this once.
Open Privacy & Security settings

Your browser will ask whether to let this page open System Settings — say yes. If nothing happens, open it by hand:  menu → System Settings → Privacy & Security, and scroll to the bottom.

On macOS 14 and earlier there is a shortcut: right-click Install.command → Open → Open. Apple removed that in macOS 15, which is why the steps above exist.

It opens today's window at the end so you can see it working.

Putting it on your MacBook Pro

Copy the folder across (AirDrop, USB, iCloud Drive — anything), then double-click Install.command on that Mac too. That is the whole job. The two Macs keep separate memories of what they have already shown you, so seeing it on one does not silence the other.

If you move the folder after installing, run Install.command again — the background job points at wherever the folder was when you installed it.

Everything lives in the calendar now

Open Student Birthdays from the Desktop and the button at the top of the page — it shows the class you are looking at — opens four panels:

PanelWhat you can do
ClassesSwitch between sets of students, remove one, or add another. Adding is drag-and-drop: drop your exports on the page and it imports them without leaving the calendar.
Preferred namesEvery student, searchable, with a box to type what you actually call them. Saves as you type. This is the panel to open when the school publishes the list.
SettingsThe 6am cutoff, the weekend warning, how far back it looks, the projector guard. No editing files.
ReminderWhether the background job is actually installed and running, when it last showed you a window, and a button to show today's window on the spot.
These only work when you open the calendar from the Student Birthdays icon. If you double-click Birthday Calendar.html directly it still works, but read-only — the page says so and tells you what to open instead.

Loading a class — and giving this to another teacher

Everything comes out of exports your school already produces. Do it from the calendar (Classes → Add a class), or open Import Students in this folder for a plain wizard. There are three files it can take. Either of the two list files is enough on its own — you never have to fetch both — and the third adds the photographs.

In iSAMS, start the same way for all three:
Student Manager → tick all your classes → Search → select all the student names → the Selected Students button → Exporting and Reports.

Whenever iSAMS offers you a format, pick Excel. All three files have to be Excel — the app reads .xlsx and .xls only, not PDF or Word.

From there, each file comes from a different place:

FileWhere, from that menuWhat it gives you
Student Report
a list file		 Students Simple Report → tick every field Names and dates of birth · year group, form, house and tutor initials
Export Wizard file
a list file, usually saved as export.xlsx		 Export Wizard → create a new export → select all the fields Names and dates of birth · preferred names — what students actually go by
Student ID Badge Custom Reports → Student ID Badge The photographs

The two list files are not the same thing and neither contains the other. Both carry all 162 names and dates of birth, so either will make a class on its own. Only the Student Report carries year group, form, house and tutor initials; only the Export Wizard file carries preferred names. As you drop files in, the panel ticks off what you are getting and marks what you are leaving behind, so nothing is a surprise.

Give it both list files if you can. With the Export Wizard alone you lose year group, form, house and which students are your own tutees. With the Student Report alone you lose preferred names. Given both, the app takes the best of each — and if two students share a name, only the Student Report can tell them apart, so their photographs are a guess without it. The import says so when it happens.

It then asks which tutor initials are yours — it reads the real list out of your report and shows it, so you just pick yours off the list — and what to call this set of students. Then it does the rest itself: every name, date of birth, year group, form, house and photograph, resized and saved as a profile under Profiles.

Nothing is hard-coded. Columns are matched by their headings, not their position, and the files are matched to each other on surname, forename and date of birth — so the order you drop them in does not matter, and a differently-ordered export still works.

Re-importing never loses your typing. Any preferred names you entered by hand are matched back on and kept. Import over the top as often as you like.

Profiles are how this travels. Run Import Students again and choose "Import a new class" for next year's students, or "Switch to" to flip between sets. Hand the whole folder to another teacher and they run Import Students with their own exports and their own initials — their tutees get flagged, not yours. Delete your class from the Classes panel first if you would rather not pass your students on with it — or ask for the blank copy, which has no class in it at all.

The one icon on your Desktop

Student Birthdays opens today's birthdays first — the same window the reminder shows you, with Got it to dismiss it and See the whole year to carry on into the calendar. On a day with nobody's birthday it skips straight to the calendar rather than making you click through nothing. Turn that off in Settings if you would rather always land on the calendar.

Everything else is inside it — the calendar, your classes, preferred names, settings, and a button to show today's birthday window on demand. The background reminder runs on its own whether or not you ever open it.

Drag it into the Dock if you would rather keep it there. If the icon looks blank or generic at first, that is macOS's icon cache — log out and back in, or just wait; it sorts itself out.

These are shortcuts, not the apps themselves. The real folder has to stay where you installed it. Move the folder and you should run Install.command again.

The calendar

Open it from the Student Birthdays Desktop icon. Three views:

  • Month — the default. Faces and first names sit in the day cells; click any highlighted day for the full cards.
  • Year — all twelve months at once, shaded darker where more than one birthday falls on a day, plus a bar of how the year is loaded. Click a month to jump to it.
  • List — every birthday in date order. This is the one that prints (⌘P) if you want a paper copy for the term.

Filter to a year group or to your tutor group with the chips, search any name, and move around with ← →, T for today, M/Y/L for views, / to search.

Across the top, Up next shows the next seven birthdays coming — click any of them to jump straight to that day.

The calendar is rebuilt from students.csv every time you open it from the Desktop icon, so edits to preferred names or students appear immediately.

Changing things

Open config.conf in TextEdit. Edit, save, done — no reinstall. The 6am cutoff, the weekend warning, how far back it looks, and the projector behaviour are all in there with plain-English comments.

Preferred names

Your active profile's students.csv (under Profiles) has an empty preferred_name column. Fill any of them in and that name is what the window shows, with the registered name underneath in small italics so you can still connect the two. Leave it blank and it uses the name from the report. Open it in Excel, or Numbers, and save as CSV.

Same file is how you add or remove one student without a full re-import: one row each, day and month are plain numbers, photo is the filename (without .jpg) in that profile's photos folder. Leave photo blank and you get a cake instead of a face.

Checking it works

Double-click the Birthday Reminder Desktop icon any time — it always shows you the window for today, even on a quiet day. That is the quickest way to confirm it is alive.

If it ever goes quiet when it shouldn't, the log is at:

~/Library/Application Support/BirthdayReminder/reminder.log

Delete that whole BirthdayReminder folder to wipe its memory and start fresh.

Turning it off

Double-click Uninstall.command. Nothing is left running.

Worth knowing

  • This folder contains 162 children's names, dates of birth and photographs. It is the same data as the reports you already hold, but two laptops is two copies — worth a glance at whatever your school's data policy says about that, and worth having FileVault on.
  • The calendar's live controls run through a tiny web server on your own Mac — bound to 127.0.0.1 with a random port and a random key, so nothing else can reach it, and it shuts itself down a couple of minutes after you close the page. Nothing is uploaded anywhere.
  • The importer needs Python, which macOS installs as part of its command line tools. If it is not there yet, the app offers to trigger Apple's own one-time installer. Nothing else is downloaded — no Homebrew, no pip.
  • There is no Notification Centre widget. A real macOS widget has to be a WidgetKit extension built and code-signed in Xcode — it cannot be made from scripts, so the Desktop icons are the honest version of that.
  • The birthday window is a browser window, not a true native alert. It cannot force itself in front of a full-screen app, and closing it makes macOS bring that browser forward. To soften this the app opens the window in a browser you do not already have running, so closing it drops you back where you were rather than raising a browser full of your own tabs. You can pin a specific browser in Settings.
  • The calendar is light-mode only. Year groups are colour-coded, but the five colours could not be made safely distinguishable for colourblind readers against a dark background, so rather than ship a dark mode that fails that test there isn't one. Every colour sits beside a written label in any case.
  • The projector guard reads how many displays are attached. On the Mac Studio, a single monitor counts as one display, so it behaves normally; plug in a second and it will go discreet even at your desk.
